# チェアサイドビュー 仕様

診療室で、手袋のまま、3つのボタンと声で必要な情報を出す画面。期間中に新しく制作。自院の既存システムのコードは不使用。

## 1. 使う人
- 歯科医師、歯科衛生士、受付の3役割。個人は見分けない。
- 上の行の色: 歯科医師 紺、歯科衛生士 緑、受付 紫。重要事項は赤い帯。

## 2. 全体の流れ
0. 作品を開くと最初に入口の画面が出る（G21n）。受付の端末は「受付モード」、ユニットは「臨床モード」を選ぶ。
1. 治療の前、手袋をする前に、臨床モードの予約一覧から患者様をマウスで選ぶ。
2. 処置が SPT の行は歯科衛生士の画面、それ以外は歯科医師の画面が開く。
3. 手袋をしたあとは、3つのボタンと声で操作する。
4. 次の患者様を開くと、前の患者様の表示を端末から消す。診療の記録は消さない。

## 3. 3つのボタン
画面の種類が変わっても役目は変えない。

| ボタン | 役目 | 目印 |
|---|---|---|
| 1 | 今日の内容の録音を始める、止める | 【REC】 |
| 2 | 押したときだけ声の指示を受け付ける | 【操】 |
| 3 | 画面を隠す、もう一度押すと戻す | 【隠】 |

### 2回押し
掃除などで当たっても誤作動しないよう、2回押しで動く。
- 1回目は画面の上に帯で案内を出すだけ。帯が出ている5秒の間にもう一度押すと動く。
- 帯の右端に残りの秒数を出す。何もしなければ帯は消え、何も起きない。
- 0.4秒以内に続けて2回押したら、帯を出さずにすぐ動く。
- 帯が出ている間に別のボタンを押したら、そのボタンの帯に切り替える。
- 録音中の REC と、声の受付中の操は、1回で止まる。
- 以降「ボタンを押す」は、止めるとき以外はこの2回押しを指す。

### 帯の文
帯には患者様の名前も情報も出さない。
- ボタン1: もう一度【REC】を押したら録音がはじまります
- ボタン2: もう一度【操】を押したら声の指示を受け付けます
- ボタン3: もう一度【隠】を押したら画面を隠します
  - 隠している間: もう一度【隠】を押したら画面を戻します

## 4. 録音
- 画面を占有しない。録音中は画面の右下に小さな窓を出すだけ。
- レントゲンや写真はそのまま見られる。
- 録音を止めたら、OK を待たずに自動で転送し、文字起こしと清書までを自動で進める。要約（下書き）は「今日の分をまとめて要約」のボタンで作る。患者様なしの録音だけ転送待ちにする。
- 下書きができたら右下の窓に「下書きができました」と出す。窓を押すか「下書きを開いて」で開く。話した内容の整理の欄は、一番新しい録音の下書きを先頭に出し、読み直さなくても変わる。

## 5. 受付の画面
- 受付の端末でしか出さない。声は使わず、マウスだけ。
- 入口の画面（G21n）: アドレス / 。今日の日付、題「チェアサイドビュー」（CHAIRSIDE VIEW）、横に並ぶ大きな札2つ（札ごと押せる）。左「受付モード」（受付の紫）→ /reception。右「臨床モード」（歯科医師の紺）→ /clinic。文言は院長が決めたとおり（app/views/entrance.py）。「受付」は「役割を変える」に足さない。受付はキャンセル傾向など患者様の前に出さない情報を含むため、ユニットの画面からは行けない。
- アドレス: / 入口、/clinic 臨床モードの予約一覧（氏名は伏せ字、1人ずつ「表示」と「すべて表示」）、/reception 受付用の患者様一覧、/reception?patient=番号 その患者様の受付の画面、/unit ユニットの画面、/app 録音と窓を持つ親の画面（中に入口が開く。go= で中の画面を指せる）。どちらの一覧の上の行にも右に「← 入口へ戻る」。
- 受付用の患者様一覧: 氏名は伏せ字にしない（患者様は受付の画面を見ないため。院長 11/6）。「表示」のボタンは置かない。列は 時間・カルテ番号・氏名・今日の処置・次回の予約（取ってあれば「11/20（金）」、無ければ「未定」）・来院しやすい曜日（受付の画面と同じ heat_best）・受付メモ（いちばん新しい1件。書いた時期で比べる。無ければ「—」）。今日の予約の時間の順。行を押すと受付の画面、「患者様を変える」で一覧へ戻る。数字は reception_data と同じ出どころ。

## 6. 声と Claude
- 決まった言葉は手元で照合して画面を動かす。Claude へは送らない。
- 自由な質問だけ Claude へ送る。
- Claude の仕事は3つだけ。
  1. 記録の中から聞かれた情報を探して見せる（番号を選ぶだけ。本文は記録の文字をそのまま出す）。
  2. 聞き取りの文の聞き違いを、歯科の言葉へ直す（清書）。
  3. 話した内容を整理して下書きにする。
- 診断も提案もしない。話していないことは足さない。記録に無いことは作らない。
- 人が確定するまで記録に入れない。
- 名前などの個人情報は伏字にしてから送り、戻ってきたら手元で元に戻す。
- モデル名はプログラムに書かず、設定（config/model.json）から読む。
- 鍵は環境変数 CHAIRSIDE_CLAUDE_KEY を先に使う。無ければその機能だけ「使えません」と出す。

## 7. データ
- 全部架空。本物の患者情報は扱わない。
- 見本データに本物のスタッフの名前を使わない（歯科衛生士は架空の「佐藤」）。歯科医師は院長本人の「大川内」を使ってよい（院長の判断、G21e）。
- SQLite。実行時のデータ（データベース、下書き、録音、送信の記録、取り込み前の写真）は全部 data/runtime に置き、コミットしない。
- 公開するのは、架空データを作るスクリプトと、確かめた写真だけ。

## 8. 作り方
- サーバー: Python の FastAPI。Streamlit は使わない。
- 画面: ビルドの要らない HTML、CSS、JavaScript。
- 文字起こし: このパソコンの中で faster-whisper。聞き取りだけをする（ヒントの語は40〜80語）。
- 清書: 聞き取りのすぐ後に、Claude が、その患者様の今日の予約の処置・治療計画・直近3回の治療歴と、歯科の言葉の一覧（config/dental_terms.json の glossary）を手がかりに、聞き違いを話の流れから正しい字に直した全文を返す。画面に出すのは清書（直した言葉に下線、迷う言葉に印）。聞き取りのままの文も残し、「聞き取りのまま」を押すと開く。5つに分ける要約は清書から作る。安全策は2つだけ: 数字（歯の番号・日付・薬の量）が変わったとき、清書が聞き取りの1.3倍より長いときは、聞き取りのまま出し、理由を小さく出す。清書が失敗しても要約まで止めない（「清書できませんでした」と出す）。モデルは config/model.json の purposes.polish（実測で決めた。docs/清書のモデル比べ.md）。ボタン2の声の操作は清書を待たず、聞き取りだけで動く。
- Claude: プログラムから API で呼ぶ。
- ポート: 環境変数 CV_PORT、無ければ 8840。他の端末からも開ける。
- app/routers の中のファイルを自動で読み込む。画面を足しても app/main.py は直さない。

## 9. 画面の決まり
- 基準は 1920×1030。本文14px、見出し20px、隙間14px。
- 説明文や注意書きは書かない。必要最低限の言葉だけ。
- 呼び方は「患者様」「歯科衛生士」。日付は「2026年11月6日 金曜日」の形（曜日は計算で出す）。
- 部品には固定の目印 data-part を付ける。見本でも本番でも同じ値。

## 10. 作らないもの

## 11. 決定（院長の答え）
1. 録音を止めたら OK を待たずに転送し、自動で文字起こしと清書まで進める。要約（下書き）はボタンで作る（G19b。もとは下書きまで自動だった）。患者様なしの録音と、30秒以内に OK が無い録音は「転送待ち」にする。
2. 受付は入口の画面の「受付モード」から入る（/reception。G21n で、はじめの「別の入口」から変更）。
3. config/commands.json の初期案は声の担当（voice）が作る。

## 12. データの形
- 場所は data/runtime/app.db（環境変数 CV_DATA_DIR で変えられる）。表の定義は app/db/schema.py、架空データは app/db/initial.py。
- 今日の日付はパソコンの日付（app/today.py の today()、app/db の TODAY）。撮影で止めたいときは環境変数 CV_TODAY=2026-11-06 のように指す。見本の過去の日付は「今日から何日前」の差を保って今日に合わせる（initial.py）。過去の記録は「今日」と書かず年月日で出し、「今日」は本当に今日の記録だけ。年齢は生年月日から今日で数える。
- 表: 患者様 patients（氏名と読みがな）、予約 appointments、診療回 visits、重要事項 important_notes、全身既往と服薬 medical_histories、申し送り handovers、受付メモ reception_memos、治療計画 treatment_plans（kind=plan 計画 / next 次回）、診療メモ clinical_notes、治療歴 treatment_history、写真 photos、歯の状態 tooth_status と変わる前の歯の状態 tooth_status_history（G19l）、その他粘膜疾患 mucosal_conditions、義歯 dentures、歯周検査 perio_exams と perio_teeth、メンテナンス間隔 maintenance_intervals、ケア用品の購入 care_purchases、物品購入 goods_purchases、処方 prescriptions、キャンセル cancellations、確定前の下書き drafts、後で直す音声 voice_fixes。
- 診療メモと下書きは必ず診療回につなぐ。(診療回, 患者様) の組で指すので、別の患者様の診療回にはつなげない。
- 下書きは status=draft の間は記録ではない。人が確定したら confirmed にする。
- 記録（G19m）: 記録は1回言えば入る（「カルテに記録する」「記録」「確定する」「確定」）。「他の画面にも入れる」候補は、歯ごとの処置（G19l）に、次回の予定（「次回の予定」の各行→次回の予定 kind=next。受付の次回と「次回は？」が読む）と治療方針（「今後の治療方針」の各行→治療方針 kind=policy。古い方針は superseded_on を付けて残し、全画面の「前の治療方針」で見られる）を足した1つの仕組み（app/ai/reflect.py）。候補は初めから印が付いていて、人が外したものだけ入らない（声は「3番 外す」「3番 付ける」）。次回の予定・治療方針は、印のある行で今のものを置き換える。
  記録で変わる所（診療メモ・治療計画・歯の状態・治療歴・次回の予定・治療方針・予約の「済み」）は、全部同じ1つの取引で書き、1行ずつ record_changes（どの表のどの行をどう変えたか）に残す。書けないものが1つでもあれば記録ごと止める。治療計画を変えたときの新しい計画は、古い計画の順番を引き継ぐ。
  取り消し: ユニットの画面で「記録を取り消す」（その日のうちだけ。次の日は「その日のうちだけ取り消せます」）。record_changes を逆にたどって全部を記録する前へ戻し、下書きの画面へ戻る（直してもう一度記録できる）。あとの記録が同じ患者様にあれば、先にそちらを取り消す。音声は記録のときに消えているので戻らない。
  記録したあとの画面: 今日の処置の大きな1行と歯の絵の「今日の歯」は、記録した「やったこと」。予約は「済み」（予約一覧に「済み」の印、受付の回数・最近の来院が読む）。AIの記録の番号に、次回の予定・治療方針と、新しい歯周検査の数字（4mm以上の歯と深さ・出血・PCR・動揺。計算は画面と同じ perio_exam()）が入る。メンテナンスの「前回」は、保存した値ではなく、この診療日より前の歯科衛生士の最後の診療回（無ければ最後の歯周検査）の日付。
  写真の数の見張りは、QR の窓とは別に、ユニットの画面が開いている間ずっと動く。
- 歯ごとの処置（G19l）: 下書きの「やったこと」の行で、歯が1本に決まり（tooth_chart.site_teeth。複数の歯・顎や側の言葉が混ざる行は決めない）、処置の言葉が config/tooth_treatments.json の表にあるものだけを、下書きの画面に「歯ごとの処置」の候補で出す。初めは全部「反映しない」。人が選んだものだけ、確定の取引の中で歯の状態（tooth_status。古い状態は tooth_status_history に診療回の日付で残す）と治療歴（診療回の日・歯・処置の名前）へ書く。Claude は関わらない。書けなければ確定ごと止める。同じ歯の同じ所を2つの処置で変える選び方は受け付けない。表の言葉: 根管充填・根充→根を根充済、抜髄・感染根管治療・根管貼薬・根管形成→根を根治中、抜歯→欠損、CR充填→歯冠CR・カリエスを外す、インレー装着→歯冠インレー、クラウン装着→歯冠クラウン、インプラント埋入→インプラント。
- 写真の番号は患者様の中の通し番号で、撮影日をまたいで重ならない。画像は data/runtime/photos に置き、seed を動かしても消さない。
- 歯番は FDI（右上 11〜18、左上 21〜28、左下 31〜38、右下 41〜48）。歯周検査は、基本検査が1本に1つのポケット、精密検査が1本に6点（頬側の遠心・中央・近心、舌側または口蓋側の遠心・中央・近心）。プラークは近心・遠心・頬側・舌側の4桁。検査の種類は perio_exams.kind（basic / precise）、6点は perio_teeth.pockets6（カンマ区切り）と bops6（0/1 の6文字）、時刻は perio_exams.exam_time。精密検査の pocket は6点の最大、bop は6点のどれかに出血があれば1（古い読み方でも読める）。基本検査の行は pockets6・bops6 が空。
- 受付の「来院しやすい曜日」「過去1年の来院」は診療回から数える。予約日・診療日は YYYY-MM-DD、時刻は HH:MM。
- 架空の5人: 見本 花子 0123 / 一郎 0456 / 太郎 0789 / 和子 1024 / 美咲 2048。今日の予約は6行。
- scripts/seed.py は data/runtime を初期の状態へ戻す（何回でも同じ）。scripts/update_db.py は無ければ同じ状態で作り、あれば足りない表・列・初期データの行だけ足す。

## 14. 決まった言葉の照合（G13 で決定）
- 照合は手元（app/voice/interpret.py）で行い、表は config/commands.json（列: 言葉、使える画面、状態、結果）。言った全体が表の言葉に合うときだけ動かす。語尾の「する」は「して」と同じに扱う。
- 聞き取った言葉は 操作 / 質問 / 無関係 / 聞き取り失敗 に分ける。今は操作だけ動かす。質問は Claude に記録の番号を選ばせて答える（G16。「まだ答えられません」は質問が使えないときだけ）、無関係と聞き取り失敗は「もう一度お願いします」と出す。
- G22 で全部の全画面が使える（「未実装」の行は無い）。全身既往・今日の処置・治療歴・歯周検査も、重要事項と同じ言葉で開く（歯周は「歯周検査」。古い言い方の「歯周基本検査」でも開く）。
- 受付の画面では声を使わない。/unit?typed=1 で文字の口、&hide=1 で入力欄を隠し window.cvTyped('言葉') で同じ操作を呼ぶ。

## 15. 写真の番号の言葉（G14 で決定）
- 写真は data/photos に置き、一覧は data/photos/photos.json（置き場は環境変数 CV_PHOTO_DIR）。今は撮った写真17枚と診察券の裏面2枚（C:\hackathon\photos_in から python scripts/import_photos.py で入れる。位置情報などは消し、長い辺は1600pxまで。見本 花子様は1〜17番、診察券は受付の画面の「診察券 裏面」）。患者様の中の番号 n は、一覧の (n-1) 番目（件数で折り返す）の画像を使う。本物に差し替えるときは画像と file を書き換える。
- ふつうの画面の欄は、撮影日ごとにまとめ、新しい日が左上。古い日はスクロールで見る。全画面は、右に一覧と同じ大きさの写真、左に選んだ写真（2.5倍）。
- 言葉: 「3番を拡大して」「1番と3番を大きく」「1番と3番と10番を大きく」（複数は左に同じ大きさで並ぶ）、「一覧に戻す」（全画面を閉じる）、「次のページ」「前のページ」。無い番号は「その番号はありません」と出し、画面は変えない。
- 隠して戻しても、拡大の状態は残る。

## 16. 言葉の揺れと丸の番号（G14c で決定）
- 言葉の表（config/commands.json）の書き方に (あ|い|) を足した。どれか1つに合う（空も可）。{n1} は数字の欄のまま。表は読み直しを避け、ファイルが変わったときだけ読む（速さのため）。
- 戻す: 「もとに戻す」「元に戻す」「もとに戻して」「元に戻して」「戻す」「戻して」「閉じて」は、全部同じ全画面を閉じる操作。
- 助詞が抜けても開く: 「重要事項全画面表示」「重要事項全画面」「重要事項の全画面表示」「重要事項全画面にして」。全身既往・今日の処置・治療歴・歯周検査・写真・話した内容も同じ形。

## 19. スマホで写真を受け渡す（G25 で決定）
- 写真の欄の「スマホ」を押すと QR を出す。有効期限は10分で、残り時間（例: 残り 9:58）を出す。切れたら「期限が切れました」と出て、QRをもう一度出せる。
- QR の中身は `<アドレス>/m/<43文字の乱数>`。サーバーはその文字列の sha256 だけを phone_links（患者様・作った時刻・期限）に持つ。文字列そのものは保存しない。
- 読むとスマホに「No. 0123」（カルテ番号。名前は出さない）と「写真を入れる」「写真を取り出す」の2つのボタンが出る。ログインもアプリも要らない。
- 入れた写真は、画像だと確かめ（中身の見出しと Pillow での読み込み）、向きを直し、撮影場所などの付属の情報を捨てて JPEG にして data/runtime/photos に置く。写真の欄に、その患者様の次の番号で入る（今日の日付）。上限は 10MB・8000万画素・1つのQRで60枚。画像以外（SVG・PDF・見出しだけ画像）は 415、大きすぎは 413。
- 取り出せるのは、そのQRの患者様の今日の写真だけ。選んで保存する（共有の窓があればそれ、無ければ保存）。
- 画面の表示・写真の取得・写真の送信の全部で、毎回その文字列と期限を調べる（app/mobile/links.py の lookup 1か所）。期限切れは 410、知らない文字列は 404。別の患者様の番号・古い日の写真は「無い」と同じ答え。
- 入れた時刻と取り出した時刻は phone_events（kind=入れた／取り出した、写真の番号、時刻）に残す。取り出しは保存のとき（dl=1）だけ記録する。
- スマホの処理は別のポートの小さなサーバー（app/mobile/server.py）にまとめる。ポートは環境変数 CV_MOBILE_PORT、無ければ 8841（試験は 8861）。開けるのは /m/ の下だけで、患者様の一覧や画面の情報は取れない。メインの起動と一緒に裏で動く（CV_MOBILE_AUTOSTART=0 で止める。`python -m app.mobile` でも単独で動く）。外から届けるのは 8841 だけにする前提。
- QR のアドレスは C:\hackathon\public_url.txt（環境変数 CV_PUBLIC_URL_FILE か config/mobile.json で場所を変えられる）の1行目。http(s) の形でなければ、または無ければ院内のアドレス（このパソコンの院内IP:ポート）。
- 画面側: 「スマホ」を押している間、2.5秒ごとに写真の枚数を数え、増えたら画面を読み直して番号付きで出す。
- G25b/G25c: QR は画面の高さの約6割（診療台から1メートルほど離れても読める大きさ）で、svg に viewBox を付けて書き出す。ボタン「スマホで写真をやり取り」は、写真の欄の右上（歯科医師・歯科衛生士の両方）と、写真の全画面の枠の中に置く。上の行の固定のボタンは置かない。押した合図は捕まえる段（キャプチャ）で受け、必ず QR の画面を開く。

## 20. 歯周検査の入力（G24・G24b で決定）
- 「入力」を押すと表が入力できる状態になり、全部の歯が未入力になる。声の入力は無い。「やめる」で元に戻る。
- ポケットの数字を押すと一覧（1〜10mm）が出て、選ぶと変わる。同じ一覧の下の段（赤い数字）で選ぶと BOP が付く。BOP は数字を赤く太く、4mm以上は背景に色を付ける。動揺度は 0〜3 の一覧。
- プラークは四角を × で4つに分けた面を押すと赤くなり、もう一度押すと戻る（近心・遠心・頬側・舌側）。
- 保存は POST /api/perio/save。今日の日付の新しい検査として入り、過去の検査は変えない。上の数字を計算し直して前回と並べる。
- 検査する歯は初期データで決める（一番新しい検査の歯、無ければ欠損でない歯）。欠損の入力は無い。未入力のポケットが1本でもあれば保存を止め、その歯を示す。
- 計算（四捨五入で整数）: 検査した歯＝検査する歯の本数、4mm以上＝ポケット4以上の歯の本数、BOP＝BOPのある歯÷検査した歯、PCR＝赤い面÷（検査した歯×4）、動揺のある歯＝動揺度1以上の歯の本数。

### G24b: 歯周検査の欄（基本検査と精密検査を同じ表にそろえた）
- 見出しは「歯周検査」。声の番号（9番）は変えない。言葉は「歯周検査…」（古い「歯周基本検査…」でも開く）。
- 欄にはいちばん新しい検査を1つだけ出す。基本か精密かは表を見れば分かるので、見る画面に「精密」「基本」の文字は出さない。
- 部品は app/mockview/perio_parts.py の1つ。見本・本物・全画面・入力が同じ表を使い、違うのはポケットの行だけ（基本＝PD の1行・1本に1マス、精密＝上は頬側・口蓋側、下は舌側・頬側の2行・1本に3マス）。
- 上の帯: PCR・BOP率・動揺のある歯（本数）・検査した歯（本数）を大きな数字＋小さな説明で。PCR と BOP率に「前回 ○%」。その右に検査の日付（2026/10/23）、曜日を赤の丸かっこ（金）、時刻を小さく。時刻は検査したときの時刻（perio_exams.exam_time）。入っていない古い検査は、その日の診療回の開始時刻を使う。
- 表: 上に「右」「左」。左端が行の名前の列。歯は 8〜1 ｜ 1〜8。真ん中に太い縦線（上から下まで）。上は 動揺度・ポケット・プラーク、真ん中に番号の帯（薄い灰色の地・大きな太字）、下は プラーク・ポケット・動揺度。BOP は赤の太字で大きめ、プラークは四角を対角線で4つの三角にして付いた面を赤、無い歯は斜線。線は薄い灰色、字は濃い色、強調は赤だけ。精密の3マスは見たままの並び（右側の歯＝遠心・中央・近心、左側の歯＝近心・中央・遠心）。
- 表の下の凡例: 「4 赤の太字 = 出血(BOP)」「▼ プラーク」「斜線 = 欠損・対象外」。精密検査のときだけ「3マスは見たままの並び（…）」を足す（「精密」の文字は出さない）。
- 割合: PCR＝赤い面÷（検査した歯×4）。BOP率は基本＝出血のある歯÷歯の数、精密＝出血の点÷（歯の数×6）。四捨五入。
- 入力: 「入力」を押すと、最初に「基本検査｜精密検査」の2つ並びの切り替えが出る（選んだ方が赤）。表は GET /api/perio/blank?appt=…&kind=… が同じ部品で返す（検査する歯だけ、値は未入力）。種類を切り替えると入れた数字は消える（画面にそう出る）。精密は1本に6点を入れる（ポケット1〜10mmと赤い数字の出血）。保存は POST /api/perio/save（kind と、基本は pocket・bop、精密は pts・bops の6つ）。今日の日付の新しい検査として入る。1日に1回までで、同じ日の2回目は「今日の検査はもう保存されています」で止める。
- Claude が読む歯周検査（ai/records.py）は検査の日付だけで、ポケットの値は読まない。見出しだけ「歯周検査」にした。
- 歯科医師の画面には歯周検査の欄は無い（衛生士の画面だけ）。
- 全画面は1ページに1回分を大きく出す。字は大きくなり、画面に収まる（スクロールは出ない）。

- 失敗は黙って飲み込まない。data/runtime/error_log.txt に、いつ・どこで・何が起きたかを1行ずつ残す（患者様の名前や記録の中身は書かない。app/errlog.py）。

## 26. 番号に5と8を使わない（G14n で決定）
- ユニットは音楽が流れていて、マイクが「5番」「8番」を聞き違えた（「ぼばん」「ごま」「たちば」など）。声で呼ぶ番号は、どの場面でも 5 と 8 の2つだけを飛ばす（15、18 などは長い言葉で聞き取れるので使う）。並びは 1、2、3、4、6、7、9、10、11、12…。
- 決まりは1か所: app/numbering.py の label(何番目か)→番号、seq_of(番号)→何番目か。JS は app/static/js/numrule.js（CVNumRule.label / seqOf）。2つが同じ答えかは tests/test_g14n.py で確かめる。場面ごとに番号を書き並べない。
- config/numbers.json の値は、部品の「何番目か」（1〜10）。/voice/numbers が label() を通した番号を返す。今の番号: 重要事項1、全身既往2、今日の処置3、治療歴4、写真6、話した内容7、歯周検査9、言える言葉10、役割を変える11、スマホ12。
- 写真: photos.number（通し番号）は書き換えない。画面の札（data-n・番号の丸）と声の番号だけを label(通し番号) で作る。「写真の10番」は札が10の写真（通し番号8）。話した内容の整理・下書き・QR の画面のボタンの番号も label() を通す。
- 「5番」「8番」と言っても何も開かない（札に無い番号と同じ扱い。「その番号はありません」）。4は「よんばん」、7は「ななばん」の読みは G14l のまま。

## 27. 見本の日付を今日へ合わせる（G21l で決定）
- 決まりは app/db/dates.py の1か所。データベースに「見本の BASE（2026-11-06）の日を、何日に合わせたか」の印を1つ持つ（app_meta の dates_aligned_to）。印の日と今日（app/today.py の today()）の差の日数だけ、SHIFT の欄を一度にずらし、印を今日にする。差が0なら何もしない。日付を戻したとき（差がマイナス）も同じ。
- 通す場所: ①データベースを開くとき（app/db/__init__.py の connect。サーバー起動後の最初の読み込み、夜をまたいだあとの次の読み込み。同じ日の2回目からは調べない）②見本を作る・足すとき（app/db/update.py。scripts/demo_state.py restore も最後に update_db.py を動かすので、読み込んだ直後に合う）。サーバー起動時にも1回通す（app/routers/startup.py）。
- 見本の行（app/db/initial.py の build）は BASE の日付のまま書く。すでにずれているデータベースへ足す行は、印の日数だけ dates.shift_rows でそろえて入れる。
- ずらす欄（欄ごとに決める。日付の形の文字だから、では決めない）: appointments.appt_date / visits.visit_date / clinical_notes.note_date / treatment_history.done_date / photos.taken_on / treatment_plans.superseded_on / dentures.made_on / perio_exams.exam_date / maintenance_intervals.last_date / care_purchases.last_date / goods_purchases.bought_on / prescriptions.prescribed_on / cancellations.cancel_date / drafts.created_at・confirmed_at / recordings.started_at。時刻の部分は残す。診療メモの見出し（memo.title_of の「2026年11月6日にやったこと」）に入っている診療回の日付も、同じだけ直す（clinical_notes.body・drafts.body）。院長が試しに入れた録音・要約も同じだけ動く。
- ずらさない欄: patients.birth_date（年齢が変わるため）/ appointments.start_time・end_time、visits.start_time、perio_exams.exam_time（時刻だけ）/ medical_histories.since・important_notes.period・reception_memos.written_on（年・年月だけの文字）/ treatment_plans.timing（「2週間後」などの言葉）/ recordings.updated_at・deleted_at（機械が待ち時間を測る時刻。ずらすと「何秒前」が狂う）/ phone_links.created_at・expires_at（QR の期限の秒）/ phone_events.at / voice_fixes.created_at（機械の記録時刻）。
- 日付・時刻に見える欄は、SHIFT か KEEP のどちらかに必ず書く（tests/test_g21l.py が、欄の名前から確かめる。新しい欄を足すと、ここで気づく）。
- 印の無い古いデータベース・控え（C:\hackathon\demo_states）: 見本は毎回同じ中身で作られるので、見本の「今日」の最初の予約（initial.build() の appointments のうち appt_date が BASE の最初の行。番号・患者様・開始時刻・役割で見本の行と確かめる）の今の日付が、BASE をずらした先の日。それを印にする（ずらす日数は、そのあとの「今日との差」）。空のデータベースは BASE。見本の行が見つからない・変わっているときは、間違った日数でずらさず、今日を印にして data/runtime/error_log.txt に残す。控えのファイル自体は書き換えない（読み込んだあとのデータベースに印がつく。今回からの save は印つきで写す）。
- 読み込んだ時の日付で固まる所はなくした: app/db/initial.py の TODAY、app/db/__init__.py の TODAY、app/mockview/parts.py の DATE（→ date_text()）、views/data.py・views/render.py・routers/drafts.py・mobile/server.py の TODAY は、使うたびに today() を聞く。
