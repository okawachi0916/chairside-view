# チェアサイドビュー 仕様

診療室で、手袋のまま、ボタン1つと声で必要な情報を出す画面。期間中に新しく制作。自院の既存システムのコードは不使用。

## 1. 使う人
- 歯科医師、歯科衛生士、受付の3役割。個人は見分けない。
- 上の行の色: 歯科医師 紺、歯科衛生士 緑、受付 紫。重要事項は赤い帯。

## 2. 全体の流れ
1. 治療の前、手袋をする前に、予約一覧から患者様をマウスで選ぶ。
2. 処置が SPT の行は歯科衛生士の画面、それ以外は歯科医師の画面が開く。
3. 手袋をしたあとは、3つのボタンと声で操作する。
4. 次の患者様を開くと、前の患者様の表示を端末から消す。診療の記録は消さない。

## 3. 3つのボタン
画面の種類が変わっても役目は変えない。

| ボタン | 役目 | 目印 |
|---|---|---|
| 1 | 今日の内容の録音を始める、止める | 【REC】 |
| 2 | 押したときだけ声の指示を受け付ける | 【操】 |
| 3 | 画面を隠す、もう一度押すと戻す | 【隠】 |

### 2回押し
掃除などで当たっても誤作動しないよう、2回押しで動く。
- 1回目は画面の上に帯で案内を出すだけ。帯が出ている5秒の間にもう一度押すと動く。
- 帯の右端に残りの秒数を出す。何もしなければ帯は消え、何も起きない。
- 0.4秒以内に続けて2回押したら、帯を出さずにすぐ動く。
- 帯が出ている間に別のボタンを押したら、そのボタンの帯に切り替える。
- 録音中の REC と、声の受付中の操は、1回で止まる。
- 以降「ボタンを押す」は、止めるとき以外はこの2回押しを指す。

### 帯の文
帯には患者様の名前も情報も出さない。
- ボタン1: もう一度【REC】を押したら録音がはじまります
- ボタン2: もう一度【操】を押したら声の指示を受け付けます
- ボタン3: もう一度【隠】を押したら画面を隠します
  - 隠している間: もう一度【隠】を押したら画面を戻します

## 4. 録音
- 画面を占有しない。録音中は画面の右下に小さな窓を出すだけ。
- レントゲンや写真はそのまま見られる。
- 録音を止めたら、OK を待たずに自動で転送し、文字起こしと下書きまで進める。患者様なしの録音だけ転送待ちにする。
- 下書きができたら右下の窓に「下書きができました」と出す。窓を押すか「下書きを開いて」で開く。話した内容の整理の欄は、一番新しい録音の下書きを先頭に出し、読み直さなくても変わる。

## 5. 受付の画面
- 受付の端末でしか出さない。声は使わず、マウスだけ。

## 6. 声と Claude
- 決まった言葉は手元で照合して画面を動かす。Claude へは送らない。
- 自由な質問だけ Claude へ送る。
- Claude の仕事は2つだけ。
  1. 記録の中から聞かれた情報を探して見せる。
  2. 話した内容を整理して下書きにする。
- 診断も提案もしない。話していないことは足さない。記録に無いことは作らない。
- 人が確定するまで記録に入れない。
- 名前などの個人情報は伏字にしてから送り、戻ってきたら手元で元に戻す。
- モデル名はプログラムに書かず、設定（config/model.json）から読む。
- 鍵は環境変数 CHAIRSIDE_CLAUDE_KEY を先に使う。無ければその機能だけ「使えません」と出す。

## 7. データ
- 全部架空。本物の患者情報は扱わない。
- SQLite。実行時のデータ（データベース、下書き、録音、送信の記録、取り込み前の写真）は全部 data/runtime に置き、コミットしない。
- 公開するのは、架空データを作るスクリプトと、確かめた写真だけ。

## 8. 作り方
- サーバー: Python の FastAPI。Streamlit は使わない。
- 画面: ビルドの要らない HTML、CSS、JavaScript。
- 文字起こし: このパソコンの中で faster-whisper。
- Claude: プログラムから API で呼ぶ。
- ポート: 環境変数 CV_PORT、無ければ 8840。他の端末からも開ける。
- app/routers の中のファイルを自動で読み込む。画面を足しても app/main.py は直さない。

## 9. 画面の決まり
- 基準は 1920×1030。本文14px、見出し20px、隙間14px。
- 説明文や注意書きは書かない。必要最低限の言葉だけ。
- 呼び方は「患者様」「歯科衛生士」。日付は「2026年11月6日 金曜日」の形。
- 部品には固定の目印 data-part を付ける。見本でも本番でも同じ値。

| 部品 | data-part |
|---|---|
| 今日の予約 | today-appointment |
| 重要事項 | important |
| 全身既往 | medical-history |
| 今日の処置 | today-treatment |
| 治療計画 | treatment-plan |
| 過去の診療メモ | past-notes |
| 治療歴 | treatment-history |
| 口腔内写真 | intraoral-photos |
| 歯の状態 | tooth-chart |
| 話した内容 | spoken-summary |
| 写真欄 | photo-list |
| 歯周基本検査 | perio-exam |
| 次回の予約 | next-appointment |
| 予約済み | booked-appointment |

## 10. 作らないもの
カメラ、顔認識、手書き文字の読み取り、レントゲンの解析、本物のシステムとの連携、アクセス権限の管理、歯周検査の声の入力、口腔内カメラの起動。

## 11. 決定（院長の答え）
1. 録音を止めたら OK で転送し、自動で文字起こしと下書きまで進める。患者様なしの録音と、30秒以内に OK が無い録音は「転送待ち」にする。
2. 受付は /reception という別の入口にする。
3. config/commands.json の初期案は声の担当（voice）が作る。

## 12. データの形
- 場所は data/runtime/app.db（環境変数 CV_DATA_DIR で変えられる）。表の定義は app/db/schema.py、架空データは app/db/initial.py。
- 今日の日付は 2026年11月6日 に固定（app/db の TODAY）。年齢は生年月日から数える。
- 表: 患者様 patients（氏名と読みがな）、予約 appointments、診療回 visits、重要事項 important_notes、全身既往と服薬 medical_histories、申し送り handovers、受付メモ reception_memos、治療計画 treatment_plans（kind=plan 計画 / next 次回）、診療メモ clinical_notes、治療歴 treatment_history、写真 photos、歯の状態 tooth_status、その他粘膜疾患 mucosal_conditions、義歯 dentures、歯周検査 perio_exams と perio_teeth、メンテナンス間隔 maintenance_intervals、ケア用品の購入 care_purchases、物品購入 goods_purchases、処方 prescriptions、キャンセル cancellations、確定前の下書き drafts、後で直す音声 voice_fixes。
- 診療メモと下書きは必ず診療回につなぐ。(診療回, 患者様) の組で指すので、別の患者様の診療回にはつなげない。
- 下書きは status=draft の間は記録ではない。人が確定したら confirmed にする。
- 写真の番号は患者様の中の通し番号で、撮影日をまたいで重ならない。画像は data/runtime/photos に置き、seed を動かしても消さない。
- 歯番は FDI（右上 11〜18、左上 21〜28、左下 31〜38、右下 41〜48）。歯周基本検査は1本に1つの数字、プラークは近心・遠心・頬側・舌側の4桁。
- 受付の「来院しやすい曜日」「過去1年の来院」は診療回から数える。予約日・診療日は YYYY-MM-DD、時刻は HH:MM。
- 架空の5人: 見本 花子 0123 / 一郎 0456 / 太郎 0789 / 和子 1024 / 美咲 2048。今日の予約は6行。
- scripts/seed.py は data/runtime を初期の状態へ戻す（何回でも同じ）。scripts/update_db.py は無ければ同じ状態で作り、あれば足りない表・列・初期データの行だけ足す。

## 13. 接続方式（G08 で決定）
- 方式: 院内HTTPS方式。マイクはブラウザの決まりで https か localhost でしか使えないため。
- 開くアドレス: https://chairside.shika.life
- 確かめ用のページ: /voice-test（声の通り道だけ。見本の画面にはつながない）。
- キーの設定は config/keys.json（ボタン1 Ctrl+Shift+F6、ボタン2 Ctrl+Shift+F7、ボタン3 Ctrl+Shift+F8、帯の時間 double_press_ms: 5000、続けて押したとみなす時間 quick_press_ms: 400）。
- 2回押しと帯は app/static/js/voice_keys.js の1か所にまとめ、3つのボタンで同じものを使う。

## 14. 決まった言葉の照合（G13 で決定）
- 照合は手元（app/voice/interpret.py）で行い、表は config/commands.json（列: 言葉、使える画面、状態、結果）。言った全体が表の言葉に合うときだけ動かす。語尾の「する」は「して」と同じに扱う。
- 聞き取った言葉は 操作 / 質問 / 無関係 / 聞き取り失敗 に分ける。今は操作だけ動かす。質問は「まだ答えられません」、無関係と聞き取り失敗は「もう一度お願いします」と出す。
- 状態が「未実装」の行（G12 の3つ以外の全画面）は「まだ開けません」と出す。
- 受付の画面では声を使わない。/unit?typed=1 で文字の口、&hide=1 で入力欄を隠し window.cvTyped('言葉') で同じ操作を呼ぶ。

## 15. 口腔内写真の番号の言葉（G14 で決定）
- 写真は data/photos に置き、一覧は data/photos/photos.json（置き場は環境変数 CV_PHOTO_DIR）。今は架空の絵12枚（scripts/make_photos.py）。患者様の中の番号 n は、一覧の (n-1) 番目（件数で折り返す）の画像を使う。本物に差し替えるときは画像と file を書き換える。
- ふつうの画面の欄は、撮影日ごとにまとめ、新しい日が左上。古い日はスクロールで見る。全画面は、右に一覧と同じ大きさの写真、左に選んだ写真（2.5倍）。
- 言葉: 「3番を拡大して」「1番と5番を大きく」「1番と5番と10番を大きく」（複数は左に同じ大きさで並ぶ）、「一覧に戻す」（全画面を閉じる）、「次のページ」「前のページ」。無い番号は「その番号はありません」と出し、画面は変えない。
- 隠して戻しても、拡大の状態は残る。

## 16. 言葉の揺れと丸の番号（G14c で決定）
- 言葉の表（config/commands.json）の書き方に (あ|い|) を足した。どれか1つに合う（空も可）。{n1} は数字の欄のまま。表は読み直しを避け、ファイルが変わったときだけ読む（速さのため）。
- 戻す: 「もとに戻す」「元に戻す」「もとに戻して」「元に戻して」「戻す」「戻して」「閉じて」は、全部同じ全画面を閉じる操作。
- 助詞が抜けても開く: 「重要事項全画面表示」「重要事項全画面」「重要事項の全画面表示」「重要事項全画面にして」。全身既往・今日の処置・治療歴（まだ開けません）、口腔内写真、話した内容も同じ形。
- 丸の番号: ボタン2の聞き取りが始まったら画面を少し暗くして、全画面ボタンの上に大きな丸の番号（76px、字52px）を出す。聞き取りが終わったら消す。受付の画面では出さない。画面を隠している間も出さない。
- 番号は部品ごとに固定（config/numbers.json）: 1 重要事項、2 全身既往・服薬、3 今日の処置、4 治療歴、5 口腔内写真、6 話した内容の整理、7 歯周基本検査。歯科医師用と歯科衛生士用で同じ部品は同じ番号。画面に無い部品の番号は出さない。
- 全画面がまだ無い部品（2・3・4・7）も番号を出し、言われたら「まだ開けません」と出す。全画面の中には番号を出さない（戻すときは「戻して」と言う）。決まりは2つだけ: 画面に見えている番号を言う。戻すときは「戻して」と言う。
- 番号の言葉: 「1番」「一番」「いちばん」「1番です」「いちばんで」「1」、長めの「1番を開いて」「1番を全画面にして」。4 は「よんばん」、7 は「ななばん」だけ（「しばん」「しちばん」は表に入れない）。番号が出ている間だけ効く。出ていないとき「番号は出ていません」、出ていない番号は「その番号はありません」と出す。
- いつもの画面で丸が出ている間は、「3番」「3番を開いて」「3番を拡大して」は全部、部品の3を開く（写真の欄の番号はその間は出さない）。写真の番号は口腔内写真の全画面の中でだけ効く（「3番」「3番を拡大して」「1番と5番を大きく」）。「口腔内写真の3番を拡大して」はいつもの画面からでも開く。
- 質問（「前回は何をした？」）はこれまでどおり。番号の丸は文字の口の試験では window.cvNumbers(true) で出す（入力欄の「番号」ボタンでも出せる）。言葉を送ると消える。
- 時間のログ: 声のあと画面が変わるまでを、文字起こし（録音を止めてから文字が返るまで）・判定・画面の反映の3つに分け、1回の声で1行、data/runtime/logs/voice_timing.log とサーバーの画面に残す（POST /voice/timing）。言葉の中身は残さない。録音の止め方（もう一度押す・6秒）は変えていない。

## 17. 暗い画面の例文と言える言葉（G14d で決定）
- ボタン2を押して聞き取りが始まると、どの画面でも必ずどこかが暗くなり、その画面で言える例文が出る。聞き取りが終わると元に戻る。例文は画面ごとの表（config/examples.json の screens）。全画面が増えたら表に足すだけで出る。
- いつもの画面: 画面全体を暗くし、全画面ボタンの上に「1番」〜「8番」、下に質問のボタン（「前回は何をした？」「アレルギーは？」「薬は？」「次回は？」）を明るく出す。出ている言葉はそのまま言えば動く。8番は「言える言葉」（全画面の一覧。上の行のプルダウンはやめた）。
- 全画面の中: 見ている物は暗くせず、上の帯（歯科医師用などの札の行）だけを暗くして例文を出す。写真や本文は暗くしない。口腔内写真は「1番と3番を拡大して」「1番と3番を並べて」「戻して」。重要事項・話した内容・言える言葉・答えの画面は「戻して」。ページのある画面（次のページの釦が見えるとき）は「次のページ」「前のページ」も出す。画面を隠している間は「画面を隠しています」。
- 写真の言い方に「並べて」を足した（「1番と3番を並べて」「…並べて拡大して」。外からは「口腔内写真の1番と3番を並べて」）。表の照合だけ。
- 録音の開始: マイクは最初のボタン2の押しで先に開き、使ったあとも60秒は持つ（持っている間も録音はしない）。時間のログに「録音の開始 ◯ms」を足した。
- 親の画面が無い画面（/、/recordings など）で【REC】を押すと、/app?go=その画面&start=1 へ移り、中に同じ画面を開いて録音を始める（go は同じサーバーの画面だけ）。

## 18. スマホで写真を受け渡す（G25 で決定）
- 口腔内写真の欄の「スマホ」を押すと QR を出す。有効期限は10分で、残り時間（例: 残り 9:58）を出す。切れたら「期限が切れました」と出て、QRをもう一度出せる。
- QR の中身は `<アドレス>/m/<43文字の乱数>`。サーバーはその文字列の sha256 だけを phone_links（患者様・作った時刻・期限）に持つ。文字列そのものは保存しない。
- 読むとスマホに「No. 0123」（カルテ番号。名前は出さない）と「写真を入れる」「写真を取り出す」の2つのボタンが出る。ログインもアプリも要らない。
- 入れた写真は、画像だと確かめ（中身の見出しと Pillow での読み込み）、向きを直し、撮影場所などの付属の情報を捨てて JPEG にして data/runtime/photos に置く。口腔内写真の欄に、その患者様の次の番号で入る（今日の日付）。上限は 10MB・8000万画素・1つのQRで60枚。画像以外（SVG・PDF・見出しだけ画像）は 415、大きすぎは 413。
- 取り出せるのは、そのQRの患者様の今日の写真だけ。選んで保存する（共有の窓があればそれ、無ければ保存）。
- 画面の表示・写真の取得・写真の送信の全部で、毎回その文字列と期限を調べる（app/mobile/links.py の lookup 1か所）。期限切れは 410、知らない文字列は 404。別の患者様の番号・古い日の写真は「無い」と同じ答え。
- 入れた時刻と取り出した時刻は phone_events（kind=入れた／取り出した、写真の番号、時刻）に残す。取り出しは保存のとき（dl=1）だけ記録する。
- スマホの処理は別のポートの小さなサーバー（app/mobile/server.py）にまとめる。ポートは環境変数 CV_MOBILE_PORT、無ければ 8841（試験は 8861）。開けるのは /m/ の下だけで、患者様の一覧や画面の情報は取れない。メインの起動と一緒に裏で動く（CV_MOBILE_AUTOSTART=0 で止める。`python -m app.mobile` でも単独で動く）。外から届けるのは 8841 だけにする前提。
- QR のアドレスは C:\hackathon\public_url.txt（環境変数 CV_PUBLIC_URL_FILE か config/mobile.json で場所を変えられる）の1行目。http(s) の形でなければ、または無ければ院内のアドレス（このパソコンの院内IP:ポート）。
- 画面側: 「スマホ」を押している間、2.5秒ごとに写真の枚数を数え、増えたら画面を読み直して番号付きで出す。
