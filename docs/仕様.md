# チェアサイドビュー 仕様

診療室で、手袋のまま、ボタン1つと声で必要な情報を出す画面。期間中に新しく制作。自院の既存システムのコードは不使用。

## 1. 使う人
- 歯科医師、歯科衛生士、受付の3役割。個人は見分けない。
- 上の行の色: 歯科医師 紺、歯科衛生士 緑、受付 紫。重要事項は赤い帯。

## 2. 全体の流れ
1. 治療の前、手袋をする前に、予約一覧から患者様をマウスで選ぶ。
2. 処置が SPT の行は歯科衛生士の画面、それ以外は歯科医師の画面が開く。
3. 手袋をしたあとは、3つのボタンと声で操作する。
4. 次の患者様を開くと、前の患者様の表示を端末から消す。診療の記録は消さない。

## 3. 3つのボタン
画面の種類が変わっても役目は変えない。

| ボタン | 役目 | 目印 |
|---|---|---|
| 1 | 今日の内容の録音を始める、止める | 【REC】 |
| 2 | 押したときだけ声の指示を受け付ける | 【操】 |
| 3 | 画面を隠す、もう一度押すと戻す | 【隠】 |

### 2回押し
掃除などで当たっても誤作動しないよう、2回押しで動く。
- 1回目は画面の上に帯で案内を出すだけ。帯が出ている5秒の間にもう一度押すと動く。
- 帯の右端に残りの秒数を出す。何もしなければ帯は消え、何も起きない。
- 0.4秒以内に続けて2回押したら、帯を出さずにすぐ動く。
- 帯が出ている間に別のボタンを押したら、そのボタンの帯に切り替える。
- 録音中の REC と、声の受付中の操は、1回で止まる。
- 以降「ボタンを押す」は、止めるとき以外はこの2回押しを指す。

### 帯の文
帯には患者様の名前も情報も出さない。
- ボタン1: もう一度【REC】を押したら録音がはじまります
- ボタン2: もう一度【操】を押したら声の指示を受け付けます
- ボタン3: もう一度【隠】を押したら画面を隠します
  - 隠している間: もう一度【隠】を押したら画面を戻します

## 4. 録音
- 画面を占有しない。録音中は画面の右下に小さな窓を出すだけ。
- レントゲンや写真はそのまま見られる。

## 5. 受付の画面
- 受付の端末でしか出さない。声は使わず、マウスだけ。

## 6. 声と Claude
- 決まった言葉は手元で照合して画面を動かす。Claude へは送らない。
- 自由な質問だけ Claude へ送る。
- Claude の仕事は2つだけ。
  1. 記録の中から聞かれた情報を探して見せる。
  2. 話した内容を整理して下書きにする。
- 診断も提案もしない。話していないことは足さない。記録に無いことは作らない。
- 人が確定するまで記録に入れない。
- 名前などの個人情報は伏字にしてから送り、戻ってきたら手元で元に戻す。
- モデル名はプログラムに書かず、設定（config/model.json）から読む。
- 鍵は環境変数 CHAIRSIDE_CLAUDE_KEY を先に使う。無ければその機能だけ「使えません」と出す。

## 7. データ
- 全部架空。本物の患者情報は扱わない。
- SQLite。実行時のデータ（データベース、下書き、録音、送信の記録、取り込み前の写真）は全部 data/runtime に置き、コミットしない。
- 公開するのは、架空データを作るスクリプトと、確かめた写真だけ。

## 8. 作り方
- サーバー: Python の FastAPI。Streamlit は使わない。
- 画面: ビルドの要らない HTML、CSS、JavaScript。
- 文字起こし: このパソコンの中で faster-whisper。
- Claude: プログラムから API で呼ぶ。
- ポート: 環境変数 CV_PORT、無ければ 8840。他の端末からも開ける。
- app/routers の中のファイルを自動で読み込む。画面を足しても app/main.py は直さない。

## 9. 画面の決まり
- 基準は 1920×1030。本文14px、見出し20px、隙間14px。
- 説明文や注意書きは書かない。必要最低限の言葉だけ。
- 呼び方は「患者様」「歯科衛生士」。日付は「2026年11月6日 金曜日」の形。
- 部品には固定の目印 data-part を付ける。見本でも本番でも同じ値。

| 部品 | data-part |
|---|---|
| 今日の予約 | today-appointment |
| 重要事項 | important |
| 全身既往 | medical-history |
| 今日の処置 | today-treatment |
| 治療計画 | treatment-plan |
| 過去の診療メモ | past-notes |
| 治療歴 | treatment-history |
| 口腔内写真 | intraoral-photos |
| 歯の状態 | tooth-chart |
| 話した内容 | spoken-summary |
| 写真欄 | photo-list |
| 歯周基本検査 | perio-exam |
| 次回の予約 | next-appointment |
| 予約済み | booked-appointment |

## 10. 作らないもの
カメラ、顔認識、手書き文字の読み取り、レントゲンの解析、本物のシステムとの連携、アクセス権限の管理、歯周検査の声の入力、口腔内カメラの起動。

## 11. 決定（院長の答え）
1. 録音を止めたら OK で転送し、自動で文字起こしと下書きまで進める。患者様なしの録音と、30秒以内に OK が無い録音は「転送待ち」にする。
2. 受付は /reception という別の入口にする。
3. config/commands.json の初期案は声の担当（voice）が作る。

## 12. データの形
- 場所は data/runtime/app.db（環境変数 CV_DATA_DIR で変えられる）。表の定義は app/db/schema.py、架空データは app/db/initial.py。
- 今日の日付は 2026年11月6日 に固定（app/db の TODAY）。年齢は生年月日から数える。
- 表: 患者様 patients（氏名と読みがな）、予約 appointments、診療回 visits、重要事項 important_notes、全身既往と服薬 medical_histories、申し送り handovers、受付メモ reception_memos、治療計画 treatment_plans（kind=plan 計画 / next 次回）、診療メモ clinical_notes、治療歴 treatment_history、写真 photos、歯の状態 tooth_status、その他粘膜疾患 mucosal_conditions、義歯 dentures、歯周検査 perio_exams と perio_teeth、メンテナンス間隔 maintenance_intervals、ケア用品の購入 care_purchases、物品購入 goods_purchases、処方 prescriptions、キャンセル cancellations、確定前の下書き drafts、後で直す音声 voice_fixes。
- 診療メモと下書きは必ず診療回につなぐ。(診療回, 患者様) の組で指すので、別の患者様の診療回にはつなげない。
- 下書きは status=draft の間は記録ではない。人が確定したら confirmed にする。
- 写真の番号は患者様の中の通し番号で、撮影日をまたいで重ならない。画像は data/runtime/photos に置き、seed を動かしても消さない。
- 歯番は FDI（右上 11〜18、左上 21〜28、左下 31〜38、右下 41〜48）。歯周基本検査は1本に1つの数字、プラークは近心・遠心・頬側・舌側の4桁。
- 受付の「来院しやすい曜日」「過去1年の来院」は診療回から数える。予約日・診療日は YYYY-MM-DD、時刻は HH:MM。
- 架空の5人: 見本 花子 0123 / 一郎 0456 / 太郎 0789 / 和子 1024 / 美咲 2048。今日の予約は6行。
- scripts/seed.py は data/runtime を初期の状態へ戻す（何回でも同じ）。scripts/update_db.py は無ければ同じ状態で作り、あれば足りない表・列・初期データの行だけ足す。
